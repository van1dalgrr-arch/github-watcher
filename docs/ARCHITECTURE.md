# gw — архитектура

> Код проекта написан нейросетью Claude (Anthropic) по задачам автора репозитория.

Один бинарник `gw`, три режима:

| Команда         | Что делает                                                                  |
|-----------------|-----------------------------------------------------------------------------|
| `gw`            | TUI: дашборд, репозитории, PR, issues, Actions + логи, лента, логи демона    |
| `gw pr list` …  | обычный CLI для скриптов и быстрых действий                                  |
| `gw daemon`     | фоновый сервис: следит за GitHub, копит ленту, шлёт уведомления в Telegram    |
| `gw notify`     | одна проверка «GitHub → Telegram» и выход — для cron в GitHub Actions         |

Уведомления должны приходить, даже когда ноутбук выключен. Основной вариант — без своего сервера:
GitHub Actions раз в 5 минут запускает `gw notify` (тот же watcher, но с хранилищем в памяти;
состояние между запусками — JSON в переменной репозитория `GW_STATE`). `gw daemon` — для живой ленты
в TUI, его можно держать локально или в Docker.

## Потоки данных

```
                ┌──────────────── gw daemon ─────────────────┐
GitHub API ──▶  │ watcher ──▶ store (SQLite) ──▶ notify ──────┼──▶ Telegram ──▶ телефон
 (опрос)        │                │                            │
                │                ▼                            │
                │   server (Gin): /api/events /status /logs   │
                └────────────────┬─────────────────────────────┘
                                 │ HTTP, раз в 5 с
                                 ▼
GitHub API ◀──── списки, действия ── gw (TUI / CLI)
```

- **Списки и действия** (PR, merge, issues, комментарии, rerun, логи Actions) — TUI/CLI ходят в GitHub напрямую,
  демон для этого не нужен.
- **Лента событий, статус и логи демона** — только через демона: он один раз забирает события,
  хранит историю и раздаёт её TUI и телефону.

## Пакеты

```
cmd/gw/              точка входа: сигналы + cli.New()
internal/
  domain/            типы: Repo, PullRequest, Issue, WorkflowRun, Event. Ни от чего не зависит
  config/            ~/.config/gw/config + окружение; токен из `gh auth token`
  github/            interface Client + реализация на go-github                 (адаптер)
  store/             interface EventStore + SQLite (чистый Go, без cgo)          (адаптер)
  notify/            interface Notifier + правила + Telegram                     (адаптер)
  watcher/           цикл: GitHub → store → notify, статус для TUI
  server/            Gin: /health, /api/events, /api/status, /api/logs
  daemonclient/      HTTP-клиент TUI/CLI → демон
  logbuf/            последние 500 строк лога демона в памяти (вкладка Logs)
  ui/                общая палитра, значки статусов, «5м», подсветка логов Actions
  cli/               cobra-команды; без аргументов запускает TUI
  tui/               Bubble Tea: модель, вкладки, модальные окна, отрисовка
```

Правило зависимостей: `domain` ← всё остальное; `watcher`, `server`, `tui` зависят от **интерфейсов**
(`github.Client`, `store.EventStore`, `notify.Notifier`), а не от реализаций. Сборка реализаций — в `cli`.
Поэтому всё тестируется на заглушках: TUI прогоняется целиком на фейковом GitHub (`tui_test.go`),
watcher — на настоящей SQLite во временной папке и фейковом Telegram.

## Ключевые решения

- **SQLite, а не Postgres.** Один пользователь, одна таблица — отдельный сервер БД был бы лишней настройкой.
  `modernc.org/sqlite` — чистый Go, бинарник собирается с `CGO_ENABLED=0`.
- **Опрос, а не вебхуки.** Вебхукам нужен публичный URL; опрос работает с ноутбука. Источники:
  received events (только *мои* репозитории — иначе в ленту льётся активность всех, на кого подписан),
  notifications (упоминания, запросы ревью), запуски Actions в репозиториях, куда пушили за сутки.
- **Events API урезан** (с 2025 года в payload PR нет заголовка и ссылки) — недостающее дозапрашивается
  и кэшируется.
- **Дедупликация по `source_id`** (UNIQUE) + флаг `notified`: после рестарта нет дублей, а уведомление,
  которое не ушло (нет сети), повторяется на следующем тике.
- **Первый запуск молчит**: неделя истории попадает в ленту, но не на телефон. Свои действия на телефон
  тоже не шлются.
- **Telegram для телефона**: бесплатно, без своего приложения. `gw telegram <token>` сам ловит chat id.
  `Notifier` — интерфейс, ntfy/Pushover добавляются без изменений остального кода.

## Что дальше

- Ответы с телефона: бот принимает `/merge 42`, `/rerun …` — **этот код автор пишет сам**.
  Командам нужен постоянно работающий процесс (long polling), поэтому бот будет жить в `gw daemon`,
  а уведомления по-прежнему идут через GitHub Actions.
- Вебхуки как второй источник событий (мгновенно, без опроса)
- Просмотр diff PR и ревью прямо в TUI
- Автозапуск демона: launchd-агент на macOS (`gw daemon --install`)
